## 总览：3Q 是什么

3Q 是一份**可以注入到任何 AI agent 的 SKILL.md**。装上之后，你的 AI 会在输出前、执行中、交付后自动做三件事：

| 阶段 | 做什么 | 耗时 |
|------|--------|------|
| **执行前** | 预检三问，发现潜在风险 | 30 秒 |
| **执行中** | 监控三信号，偏离即修正 | 实时 |
| **交付前** | 快速 3Q 检查（10 秒）→ 不通过则深度 7 维评分 | 10 秒 ~ 3 分钟 |
| **持续** | 自修正 — 同类错误 ≥ 3 次自动添加规则 | 自动 |

**一句话**：让 AI 从"答完了就交"变成"停下来想一想再交"。

## 认知进化：六问框架

AI（和人一样）有一个天然缺陷：**困在自己的视角里**。写代码时忘了检查边界条件，做分析时默认假设成立，写内容时以为用户和自己想的一样。

3Q 的六问框架就是破解这个问题的——每个维度从不同角度突破自我视角局限：

| 维度 | 问题 | 突破什么视角 |
|------|------|-------------|
| **元认知 Q** | 我的任务理解对吗？ | 自以为是的视角 |
| **标杆 Q** | 领域顶尖 1% 怎么做？ | 低标准的视角 |
| **挑战 Q** | 如果我的假设全错了？ | 默认正确的视角 |
| **逻辑 Q** | 论证自洽吗？ | 跳跃论证的视角 |
| **用户 Q** | 用户价值清晰吗？ | 自我中心的视角 |
| **竞争 Q** | 差异化在哪？ | 盲目跟风的视角 |

六个问题不是"质量检查清单"——它们是六个不同的**认知透镜**，每一次执行都强制切换一次视角。

### 三维扩展：看见空间维度

六问突破的是"视角"，三维突破的是"广度"——你在正确层级、正确时间跨度、正确竞争位上思考问题吗？

| 维度 | 检查什么 | 突破什么局限 |
|------|---------|-------------|
| **阶维** 🏛️ | 层级匹配 | 执行层问题上升到战略层解决（打蚊子用大炮） |
| **纵维** ⏳ | 时间演变 | 只看到当下，看不到需求从哪来、往哪去 |
| **横维** 🌐 | 生态位 | 只看到自己，看不到直接/间接/替代竞品 |

**使用建议**：
- 日常检查：六问
- 深度分析：六问 + 三追问
- **重大决策：六问 + 三维 + 三追问 + 盲审**

```
┌──────────────────────────────────────────────────────┐
│             3Q 质量系统 — 三层架构                      │
├──────────────────────────────────────────────────────┤
│  Layer 0：事前预审 + 实时护栏                          │
│  Layer 0.5：快速 3Q（子任务返回后 10 秒检查）          │
│  Layer 1：六问审视 + 三维扩展 + 独立盲审               │
└──────────────────────────────────────────────────────┘
```

### Layer 0：Pre-flight + Guardrails

**事前预审三问**（每次执行前）：

```
Q1: 这次执行最可能出什么错？    → 预判风险点
Q2: 如果出错，影响什么？        → 范围评估
Q3: 怎么在执行中发现它出错？    → 检测手段
```

答不出 → 先补信息。禁止跳过。

**事中修正三信号**：

| 信号 | 触发条件 | 修正方式 |
|------|---------|---------|
| S1 产出偏离 | 与预期差距 > 30% | 暂停 → 回溯目标 → 重写 |
| S2 遗漏依赖 | 发现未读关键上下文 | 暂停 → 补充 → 继续 |
| S3 版本冲突 | 读到的版本与预期不符 | 暂停 → 确认 → 继续 |

**自动触发条件**（直接升级到深度 3Q）：
- 同类问题出现 ≥ 3 次
- 版本号声明与实际不符
- 底层改动未同步到顶层

### Layer 0.5：Quick 3Q

每次子任务返回后，10 秒过三问：

```
① 做全了吗？    ← 步骤完整性
② 做对了吗？    ← 数据偏差 ≤ 2%
③ 有反常的吗？  ← 无未确认异常
```

全部通过 → 交付。任一不通过 → 自动升级到深度 3Q。

**Grill 模式**：挑战 Q 不再走过场——每个"通"必须配一个"不通会怎样"。至少 1 条 🔴，全绿 = 没认真审。

### Layer 1：六问审视 + 三维扩展 + 盲审

#### 核心六问

| 维度 | 问题 | 目的 |
|------|------|------|
| **元认知 Q** | 我的任务理解对吗？ | 方向检查 |
| **标杆 Q** | 领域顶尖 1% 怎么做？ | 设定高标准 |
| **挑战 Q** | 如果我的假设全错了？ | 发现盲点 |
| **逻辑 Q** | 论证自洽吗？ | 内部一致性 |
| **用户 Q** | 用户价值清晰吗？ | 确保有用 |
| **竞争 Q** | 差异化在哪？ | 建立优势 |

> **标杆 Q 前置步骤**：分群 → 对标 → 冲突。不分群就谈标杆，是在用不知道哪个流派的标尺量东西。

#### 三维扩展

六问检查**质量**，三维检查**范围**：

| 维度 | 检查点 | 典型错法 |
|------|--------|---------|
| **阶维** 🏛️ | 层级匹配 — 执行层问题用执行层方案 | 一个 bug → 上升到"重新定义组织架构" |
| **纵维** ⏳ | 时间演变 — 需求从哪来？现状？趋势？ | 为临时需求盖永久架构 |
| **横维** 🌐 | 生态位 — 直接/间接/替代竞品在哪？ | 跟错竞争对手，用错差异化策略 |

#### 三追问（深度检查）

| 追问 | 问题 | 目的 |
|------|------|------|
| 副作用检查 | 这个规则会不会矫枉过正？ | 防止过度设计 |
| 重启条件 | 什么时候该承认判断失效？ | 防止错误持续生效 |
| 地基递归 | 支撑当前逻辑的最底层假设是什么？ | 防止地基歪了 |

## 量化评分体系

7 个维度，每个 1-10 分。满分 70 分，≥ 70 通过。

| 维度 | 1-3 分 | 4-6 分 | 7-9 分 | 10 分 |
|------|--------|--------|--------|-------|
| **元认知 Q** | 方向偏了 | 方向对但浅 | 理解准确 | 发现隐性需求 |
| **标杆 Q** | 没搜 | 搜了没分群 | 分群+对标 | 分群+对标+冲突 |
| **挑战 Q** | 没质疑 | 质疑了没推翻 | 找到盲点 | 推翻重建更好 |
| **逻辑 Q** | 有矛盾 | 自洽但粗糙 | 严谨 | 有反证 |
| **用户 Q** | 价值不清 | 有价值但不聚焦 | 聚焦可衡量 | 用户直接感知提升 |
| **竞争 Q** | 没差异 | 有差异但脆弱 | 可持续 | 差异化是壁垒 |
| **效果验证** | 没测 | 测了没基线 | 基线确认提升 | 量化+置信 |

**执行规则**：
- 每次深度 3Q 必须打分，无分数 = 无效审查
- 效果验证必须跑实际测试对比（有 skill vs 无 skill），不能空口评
- 总分 ≤ 60 → 直接驳回；61-69 → 盲审验证后决定

## 独立盲审

**为什么需要**：SkillLens 论文实证，AI 自审准确率仅 **46.4%**——因为"我知道为什么这么写"的解释器偏差。

3Q 的解决方案：

```
交付文件 → spawn 盲审 agent（裸读，无上下文）
         → 按六问 1-10 分独立评分
         → 主 agent 对比自有评分 + 盲审
         → 偏差 > 2 分 → 按低分处理
```

**评分收敛规则**：
- 盲审分 ≈ 主 agent 分（偏差 ≤ 1）→ 已收敛，以主 agent 为准
- 盲审分明显更低（偏差 > 2）→ 强制审查该维度，按低分处理
- 盲审分明显更高 → 检查盲审是否遗漏问题

## 自进化机制

3Q 不仅检查 AI 输出，也检查自己：

**Skill 淘汰**：`retirement_score = utility × log(use_count)`
- > 0.5 → 保留
- ≤ 0.5 → 退役候选
- 长期未使用 → 直接退役

**Meta-3Q**：同类问题连续 3 次六问不够用？外部出现新范式？→ 触发框架自我升级。

## FAQ

**Q: 3Q 和 prompt engineering 的区别？**
A: Prompt engineering 是说"你仔细检查一下"，3Q 是"按 7 个维度逐条打分，不到 70 分重来"。前者靠模型自觉，后者是结构化流程。

**Q: 为什么不直接用"review your output"？**
A: SkillLens 论文证明 AI 自审只有 46.4% 准确率。3Q 的独立盲审绕过了解释器偏差。

**Q: 需要什么依赖？**
A: 零依赖。一个 SKILL.md 文件，任何 agent 都能读。

**Q: 适用于什么场景？**
A: 代码审查、分析报告、内容创作、产品设计、决策评估。不适用实时对话和简单查询。
